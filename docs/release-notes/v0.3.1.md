# Aura 0.3.1 — Keystone

The **Keystone** release. Aura `0.3.1` is a *language* release: the release
version and the language version coincide at `0.3.1`, because Keystone changes
observable language behavior. The human-approved codename for the `0.3` line is
**Keystone**.

Aura remains a small, expression-oriented scripting language with a conservative
static checker, a native Rust runtime, an explicit-continuation evaluator on
every substrate, and a versioned in-browser WebAssembly Playground.

## Language and semantics (Keystone)

### Distinct collection identities (ADR-0005)

Aura `0.2` collapsed tuples into lists and had no distinct `Array` or `Set`.
Keystone restores a five-identity value algebra, because a shared capability
must not erase identity:

- **List** `[T]` — family `Sequence`, value kind `list`; resizable, indexable.
- **Array** `[T; N]` — family `Sequence`, value kind `array`; fixed length,
  indexable, element-mutable, **not** resizable. `N` is a compile-time
  non-negative integer literal, bounded at `2^24`.
- **Tuple** `(T, ...)` — family `Sequence`, value kind `tuple`; fixed-length,
  heterogeneous, **immutable**, indexable. `(a,)` is one-element; `(a)` is
  grouping.
- **Set** `{T}` — family `SetLike`, value kind `set`; unordered membership with
  deterministic order, not indexable, elements are key-capable scalars
  (`int`/`bool`/`string`), duplicate literal members collapse.
- **Map** `{K: V}` — family `Mapping`, value kind `map`; unchanged from `0.2`.

`List != Array != Tuple != Set != Map` in equality; a struct is never equal to a
map. AIS reports the distinct `type_name`, `families`, and `value_kind` for each.

### Fixed-length contextual Arrays

Array type syntax is `[T; N]`, where `;` separates the element type from a
compile-time length. A bracket literal stays comma-separated: `[a, b]` is a
**List** by default and becomes an **Array** only under an expected `[T; N]`
type. `[1; 2; 3]` is **not** an Array literal; `;` between elements is rejected
(`E1006`) and is reserved for the array type and for string/comment content.

Contextual realization flows through exactly one seam (checker
`check_array_literal`, runtime `eval_expected`) at an annotated `let`, a
directly resolved function argument, a declared `return`, a struct field, and a
nested bracket element. There is **no implicit conversion** between a List and
an Array, and no length covariance: an Array literal whose length or element
types do not match the expected type is a static error (`E3001`).

### Canonical type-position `json_decode_as`

The typed JSON API now takes a **type position** as its second argument, parsed
with the canonical `ty()` grammar:

```aura
struct Pokemon {
    id: int,
    name: string,
}

fn main() {
    let pokemon = json_decode_as("{\"id\":25,\"name\":\"pikachu\"}", Pokemon)
    print(pokemon.name)
}
```

This prints `pikachu`. The former string-literal spelling normalizes to the same
AST node, so there is one type path. Typed decode restores the requested
collection identity (`[T; N]` Array, `(T, ...)` Tuple, `{T}` Set) and reports a
strict `E4031` for a wrong length/arity or a missing/wrong/unknown field; an
unknown type in a type position is `E3002`. Dynamic decode still yields a List
for a JSON array. Encoding is a serialization, not an identity-preserving
round-trip: `json_encode` never silently collapses an unrepresentable kind to
`null`.

### No general semicolon sequencing

Aura's general statement/item separator is newline (or the zero-width boundary
before `}`/EOF). The `;` character is no longer a general statement separator; a
`;` in a general position is `E1006`. This makes the grammar's `[T; N]` use of
`;` unambiguous.

## Parser and runtime hardening

- Structural `TypeExpr` nesting is bounded at 256 on every substrate (`E1015`),
  with the parser backstop and the Native/WASM acceptance agreeing at the
  limit.
- Parameterized-alias expansion is bounded in depth and breadth: a pathological
  alias chain is `E1015`, never a quadratic hang or a host abort.
- Physical and in-source module nesting is bounded at 256 (ADR-0004).
- Grouping and f-string interpolation recursion is bounded, so a deeply nested
  source traps the language boundary rather than the WebAssembly host stack.
- String lexing is linear-time (`O(n)`), not `O(n²)`.
- The explicit-continuation (iterative) evaluator is the production engine on
  every entry point; the released runtime reports the normative frame-limit
  diagnostic (`E4011`) instead of a host `Maximum call stack size exceeded`.

## Diagnostics

- Source-aware spans throughout, including the typed-decode and module
  diagnostics.
- The nested type/module limit reports `E1015` at the offending node.
- Structured diagnostics with CLI color policy (`AURA_COLOR` / `NO_COLOR`).

## AIS and MCP

- AIS reports distinct collection `type_name`, families, and `value_kind`, and
  applies the anti-collapse rule, with an optional-type (`T | none`) narrowing
  projection.
- The three-level AIS/MCP facts for the typed-decode API are pinned by tests.

## Playground

- A new immutable `0.3.1` WebAssembly runtime is published and is the default;
  the frozen `0.0.2`, `0.2.0`, and `0.2.1` runtimes remain byte-for-byte
  unchanged and selectable.
- Virtual multi-file projects, standard input, and arguments work entirely in
  the browser session. The browser host has **no host filesystem**: filesystem,
  clock, and sleep report `E5002`.

## Validation infrastructure

- The macOS validation bottleneck was root-caused: the first execution of a
  freshly linked test binary paid macOS's security assessment of the ad-hoc
  linker-signed Mach-O image (30–65 s wall at ~0.00 s user CPU). The validator
  now stages each freshly linked test binary into a small scratch directory and
  executes it there, discovers the complete test surface (library unit tests,
  integration tests, the binary harness, doctests), runs each target as its own
  process group with a per-target deadline, and persists results atomically and
  incrementally for resumable runs.
- The full local matrix (`all-features`, `canonical`, `bare`) completes in
  minutes rather than timing out with no output.

## Compatibility and migration

`0.3.1` is a **language** release and is **not** a drop-in superset of `0.2.1`.
Changes a program may observe:

| Change | Kind | Who is affected |
|---|---|---|
| Tuple is no longer list sugar; `Tuple`/`Array`/`Set` are distinct | intentional break | programs that treated `(a, b)` as a list or relied on cross-kind equality |
| Array literals are contextual (`[T; N]`) | new capability | programs that want fixed-length arrays |
| `json_decode_as(text, "T")` → `json_decode_as(text, T)` | API change | programs using the string spelling (it still normalizes) |
| `;` is not a general statement separator (`E1006`) | intentional break | programs using `;` between statements |
| Set membership limited to key-capable scalars | new capability | programs wanting broader membership (deferred) |

See `docs/adr/0005-keystone-collection-model.md` and the website migration guide
for details.

## Known limitations

- Set membership is limited to key-capable scalars (`int`/`bool`/`string`);
  broader membership is deferred.
- Array length is a compile-time integer literal bounded at `2^24`; it is not a
  const-expression.
- A nested array literal passed directly as a call argument is not contextually
  realized (a nested array via `let` is); this is a known limitation carried
  from the collection work.
- HTTP remains a non-default capability; the browser host does not provide it.

## Release engineering

- A CycloneDX **SBOM** and a machine-readable **release manifest** (with a
  dependency-lock hash) are attached to the release, and build provenance is
  signed (SLSA) at publish.
- The `0.3.1` Playground runtime is shipped as a versioned, immutable artifact
  with a recorded SHA-256.
