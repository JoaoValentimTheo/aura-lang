# Aura 0.2.1

A **language** release on the `0.2.1` line (`release = language = 0.2.1`). It is
a focused, additive step over `0.2.0`: one new reservation rule and one
correction that makes nesting behavior identical on every substrate, plus a set
of robustness fixes found by independent adversarial review. Most programs need
no changes — see [`docs/MIGRATION_0_2_1.md`](../MIGRATION_0_2_1.md).

## Added

### Builtin-name reservation (`E1009`)

A user **value binding** — `let`/`let mut`, a parameter, a loop/catch/pattern
binding, a top-level `let`, a top-level `fn`, or a `use … as` alias — may no
longer reuse a registered builtin name. Type, module, field, variant, method,
and **module-member** names live in separate namespaces and are unaffected
(ADR-0002). This closes a real assignment-safety hole: previously a binding
named like a builtin could not be assigned to through the name.

## Changed

### Type nesting is bounded on every substrate (ADR-0004)

Structural nesting of a type annotation — a generic application (`Box<…>`), a
list (`[T]`), or a map (`{K: V}`) — now counts toward the semantic AST limit
(256 levels), so the ceiling is identical on native and WebAssembly. The former
native/WASM acceptance divergence is removed. A flat union (`A | B | …`) is a
list of alternatives and is not penalized per member.

### Module nesting is bounded on every substrate

In-source `module` nesting and physical directory chains both count toward the
same 256-level limit, on every substrate.

### CPython boundary uses exact-type identity

At the Python boundary, a value converts only when it is a genuine builtin
scalar instance. A user object implementing `__float__`, `__index__`,
`__bool__`, or `__str__` takes the documented `repr` fallback instead of being
silently coerced, and the rule applies to **dict keys** as well. Python→Aura
depth is bounded symmetrically with Aura→Python.

## Fixed

### Robustness (independent red-team review)

- A chain of type aliases that nests too deeply, or that expands to too many
  nodes, is now a structured `E1015` — never a host stack overflow or an
  unbounded computation. This covers plain chains, parameterized chains, and
  grow-the-argument shapes.
- Lexing a long string literal is O(n) rather than O(n²).
- Depth-limit `E1015` diagnostics now carry the exact source location of the
  offending node instead of `1:1`.

## Release engineering

- A CycloneDX **SBOM** and a machine-readable **release manifest** (with a
  dependency-lock hash) are attached to each release, and build provenance is
  signed (SLSA) at publish.
- Every frozen runtime is exercised against its language line's fixtures, and
  the installed binary is smoke-tested end to end before release.

## Compatibility

`0.2.1` is a superset of `0.2.0` for the overwhelming majority of programs. The
only intentional behavior changes are the builtin-name reservation and the
nesting bounds; a program that relied on a builtin-named binding or on an
alias chain past the semantic limit was relying on undefined or unsafe
behavior. See the migration guide for details.
