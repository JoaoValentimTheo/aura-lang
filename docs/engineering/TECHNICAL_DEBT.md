| TD-13 | MEDIUM | REPL submissions are O(N²) in session size | Each submission calls `Checker::with_declarations(&decls)` (src/repl.rs:306, 401), which loops over every prior `GlobalDecl`; N submissions cost Σk = O(N²) registration work. **Re-profiled 2026-10-01 (release):** 12/19/41/115/388/1454 ms for 100/200/400/800/1600/3200 submissions (~3.5× per doubling — clean quadratic). | **Root cause + equivalence obstacle (2026-10-01):** the full rebuild is also the rollback mechanism, and it is *not* equivalent to "keep the checker and mutate it": `check_stmt` on `let x = 5` records the *inferred* type in `value_types[0]`, whereas `with_declarations` only populates `value_types` for a binding whose persisted `ty` is `Some` (an annotated `let`); an unannotated one is left absent on rebuild. A monotonic cache would therefore type later uses more precisely than the rebuild does — an observable divergence, not just a metadata difference. A safe fix must (a) replicate `with_declarations`' exact per-variant registration including the `value_types` asymmetry, (b) restore the pre-statement state on any failed/rolled-back submission, and (c) be proven equivalent by a differential oracle over randomized submission sequences. Until then the O(N²) is confined to the interactive path (thousands of programmatic submissions) with no correctness impact, which the v1 Performance gate accepts as explicitly justified. **Re-confirmed 2026-10-29 (release):** `SessionEngine::feed_line` over `let v{i} = {i}` measured 6.8/16.0/40.9/136.5/491.7/1886.4 ms for 100/200/400/800/1600/3200 submissions (per-cell 67.8/80.1/102.3/170.6/307.3/589.5 µs). This confirms the 2026-10-01 profile rather than revising it: repeated runs of the same probe put N=400 at 40.9–42.5 ms (vs 41 recorded) and N=1600 at 384–492 ms (vs 388), i.e. a single wall-clock batch varies by up to ~25% on a shared host. N=3200 at 1886 ms vs 1454 is inside that same spread, so it is **not** a regression. A debug-build run of the same probe reports 18.4/50.0/176.9/669.6/2583.9/10230.4 ms — ~5× inflated but the same 3.5–4.0× doubling ratios; quote release numbers for this entry and treat debug timings as shape-only. Component isolation confirms the mechanism is unchanged and that the rebuild is the *entire* cost: `Checker::with_declarations` alone costs 0.52/1.02/1.77/3.37/5.76 ms at N=200/400/800/1600/3200, a linear 1.8–2.6 µs per declaration, so Σk registration work over growing `decls` fully explains the quadratic — there is no second, hidden hotspot to chase. | Static Semantics / DX | v1.1 |

| TD-24 | MEDIUM | The value encoder's byte work was quadratic in the rendered size | The AUDIT-4 budget bounds the number of nodes *visited*, so it guaranteed termination and a bounded output size, but each node collected its children into a `Vec<String>`, `join`ed them, and returned the result — so every node's whole subtree string was rebuilt and copied once per enclosing level. A value that legitimately exhausted the 1,000,000-node budget did gigabytes of `memcpy` (~3 MB output x up to 512 levels) per render. The fuzz `runtime` target surfaced it as a **libFuzzer timeout, not a crash** (artifact `f99bc20a`, seed `2913381875150184294`), which is easy to misread as "the guard is missing"; the guard was correct and already tested, the encoder was just too slow. | **FIXED** — `Value::repr` returned a fresh `String` per node; replaced by `Value::write_repr(..., out: &mut String)` appending into one shared buffer, with `Value::write_items`/`Value::write_joined` helpers and a matching `MapKey::write_repr` (keys are `int`/`bool`/`string` and cannot fan out, so they need no budget). `MAX_VALUE_NODES`/`MAX_VALUE_DEPTH` were deliberately **not** lowered: the cap was right, and shrinking it would both mask the defect and silently reduce the set of values the language renders honestly.
